## Ledger rules (`parity/test_ledger.json`, one row per reference file)

Dispositions: `ported`, `adapted`, `skipped_gap`, `non_goal`, `unaccounted` (counted MISSING).

- `ported`/`adapted`: `ash_surface_tests` lists existing `*_test.exs` (or `*.test.mjs`) files
  with no skip of any form and at least one test. Reference `.ts` files can only be
  `adapted` or `non_goal`. `adapted` needs `changes` (what changed and why).
- `skipped_gap`: `gap` text, `skip_tag` (verbatim text inside the listed test, which must
  also contain a real skip), optional `capabilities` ids from `parity/capabilities.json`.
- `non_goal`: `readme_quote` verbatim in `README.md` (whitespace-collapsed).
- A file mixing real tests and loud skips cannot back a `ported`/`adapted` row: lanes put
  loud skips in a dedicated `<name>_gap_test.exs` and list it on a `skipped_gap` row, and the
  runnable half on the `adapted` row (one reference file may be re-split by editing its row's
  `ash_surface_tests`; a row supports one disposition, so a partly-gap file takes
  `skipped_gap` only when nothing in it is portable).
- Lanes edit only their `owner_lane` rows with small targeted Edits (re-read before each).
- Adapted tests live under `test/ash_surface/ported/<dir>/` (dir = reference directory with
  `test/ash_typescript/` stripped, e.g. `ported/rpc/`, `ported/ts/should_pass/`).

## Adaptation rules by reference type

- Elixir tests asserting generated TypeScript text: `adapted` (assert the Zod/`.mjs`
  behavior under node with real zod, or the Elixir renderer's structured output) or
  `non_goal` with the README quote (no generated `.ts`/`.d.ts`/tsc build step).
- Elixir tests of runtime pipeline behavior (field selection, result shaping, error
  handling, formatting): `ported` against the ash_surface equivalent module where the
  semantics match; divergences are pinned in `docs/KNOWN_DIVERGENCES.md`, never hidden.
- TS fixtures (`shouldPass`/`shouldFail`): `adapted` to the Inference declaration block
  compiled with real `tsc --strict` (shouldFail: `// @error` markers, error count >= markers) or
  to Zod accept/reject cases under node; Valibot is a README non-goal unless a quote says
  otherwise (verify against README before claiming).
- Chicago style only: real Ash resources, real node subprocess, no doubles.

## Ordering constraints

1. T0 (this gate) lands first; `parity/test_inventory.json` is regenerated only by the
   coordinator (reference HEAD moves invalidate row evidence).
2. T4 first among the content lanes: it owns manifest/TypeFacts fixtures and the mixed-file
   split convention (`*_gap_test.exs`) that all lanes copy.
3. T5-T7 and T8-T12 share the RPC fixtures; one lane (T5) builds the shared resource
   fixtures under `test/support/ported/` first, others import read-only.
4. T15/T16/T17 depend on node + `node_modules/.bin/tsc` and zod being installed (`npm ci`);
   T17's `.test.mjs` runner must be wired into `package.json` `test` glob (`test/js/*.test.mjs`
   today) or live in `test/js/`.
5. Gaps found by a lane are implemented under the divergence law before the row may be
   `skipped_gap`; a `skipped_gap` row needs `capabilities` ids when `parity/capabilities.json`
   has a matching cell.
6. Integration is serialized by the coordinator: gate summary re-read from the gate output, not
   from this document (counts here are as-of the seed).
