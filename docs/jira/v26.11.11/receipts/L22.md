## Divergences (disclosed)

1. Same as L21: `match` renders as `.regex("<json string>")`, not a regex
   literal — ZodGuard admits string call arguments, refuses regex literals.
2. `z.record` takes one value schema for all keys; per-key discrimination
   needs function combinators outside the ZodGuard grammar — the value is
   a union of strict per-calculation arg objects (two calculations
   admitting the same arg shape are cross-satisfiable). Narrower leak
   than the charter's single merged args object.
3. Names are JSON-encoded string literals (SelectionSchema law), so
   non-identifier names are lawful and injection-safe; only empty /
   non-binary / duplicate names are refused. (The first example draft
   expected identifier-only validation — corrected against the landed
   sibling law, not papered over.)
